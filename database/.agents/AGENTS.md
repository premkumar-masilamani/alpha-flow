# AGENTS.md - Database

## Commands
```bash
# Connect to psql shell on active container
make connect_database
```

> [!CAUTION]
> **NEVER apply migrations**: Agents must NEVER run `make migrate_database`, `make run_database`, or any command that applies migrations. All migrations are strictly manual.

## Boundaries

### Always do
- Use append-only SQL migration pairs in `database/migrations/`.
- Ensure down scripts are exact reversals (`DROP TABLE IF EXISTS ... CASCADE`).
- Use `IF EXISTS` / `IF NOT EXISTS` guards for idempotency.
- Use DB migrations strictly for DDL only (schema changes).
- Author migration files only; leave execution entirely to the user (all migrations are manual).
- Author any schema updates, new columns, or alterations in a new, separately numbered migration script pair (`XXX_...up.sql` / `XXX_...down.sql`). DB migrations are executed only for new scripts; existing/already-authored migration files must never be retroactively modified.

- Name primary keys using the `<singular_table_name>_id` convention (e.g. `ticker_id`, `daily_price_id`, `indicator_definition_id`), never a generic `id`.
- Ensure all daily_* and weekly_* child tables enforce foreign keys with `ON DELETE CASCADE` from `tickers(ticker_id)`.
- Reorder columns by table recreation or swap; PostgreSQL does not support `ALTER TABLE ... MODIFY COLUMN ... FIRST/AFTER`.

### Ask first
- Any structural schema changes to historical price tables or indicator structures.

### Never do
- Apply migrations (never run `make migrate_database`, `make run_database`, `migrate`, or any automated migration execution). All migrations are manual—never ever apply them.
- Edit, retroactively update, or alter existing/already-authored migration files. All schema additions must be created in a new, separate migration script.
- Drop tables without `CASCADE`.
- Use PostgreSQL reserved keywords (`user`, `type`, `order`, etc.) for column names.

## Data Sections

### Data Sources
- **Canonical Tables**: `tickers`, `daily_prices`, `weekly_prices`, `daily_indicators`, `weekly_indicators`, `indicator_definitions`.
- **Column Types**:
  - Primary keys: `<singular_table_name>_id INT8 GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
  - Prices / Volume: `NUMERIC(18, 4)`
  - Indicator outputs: `jsonb`

### Constraints
- **Unique**:
  - Price tables: `UNIQUE (ticker_id, price_date)`
  - Indicator definitions: `UNIQUE (indicator_type, source, params)`
  - Indicator values: `UNIQUE (ticker_id, indicator_definition_id, price_date)`

### Business Rules (Multi-Market)
- US equities: `ticker_type = 'US-EQUITY'`, `currency = 'USD'`, `timezone = 'America/New_York'`.
- Indian equities: `ticker_type = 'IN-EQUITY'`, `currency = 'INR'`, `timezone = 'Asia/Kolkata'`. (Suffix `.NS` for NSE).
- Crypto: `ticker_type = 'CRYPTO'`, `currency = 'USD'`, `timezone = 'UTC'`.
- Commodities: `ticker_type = 'COMMODITY'`, `currency = 'USD'`, `timezone = 'America/New_York'`.

### Code Style
```sql
-- Uppercase keywords, snake_case identifiers, 4-space indent
CREATE TABLE IF NOT EXISTS daily_prices (
    daily_price_id INT8 GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ticker_id INT8 NOT NULL,
    price_date DATE NOT NULL,
    price_open NUMERIC(18, 4),
    price_close NUMERIC(18, 4),
    CONSTRAINT fk_daily_prices_ticker FOREIGN KEY (ticker_id) REFERENCES tickers(ticker_id) ON DELETE CASCADE,
    CONSTRAINT uk_daily_prices_date UNIQUE (ticker_id, price_date)
);
```

## Database Indices & Query Optimization
- **Functional Expression Indexes for Case-Insensitive Queries**: Standard B-tree indexes on `(column)` are not used for `LOWER(column)` expressions generated by Spring Data `findBy...IgnoreCase`. Use functional expression indexes (e.g. `CREATE INDEX idx_tickers_symbol_lower ON tickers (LOWER(ticker_symbol))`) to ensure logarithmic lookups.
- **Prefix Redundancy with Unique Constraints**: Multi-column unique constraints implicitly create underlying unique B-tree indexes. Secondary indexes whose indexed columns are a leading prefix subset of an existing unique constraint (e.g. `idx_dsr_ticker_date (ticker_id, price_date)` covered by `uk_daily_support_resistances (ticker_id, price_date, zone_bottom, zone_top)`) are redundant and must be omitted to prevent disk bloat and write I/O degradation.
- **Foreign Key Indexing on Cascade Child Tables**: Foreign key columns on child tables referencing parent tables with `ON DELETE CASCADE` (such as `indicator_definition_id` on `daily_indicators` / `weekly_indicators`) should have dedicated indexes unless covered by the leading column of a composite key to prevent sequential table scans on parent deletions/updates.
