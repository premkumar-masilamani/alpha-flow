# AGENTS.md - Database

Operational guidance for AI coding agents working on database schemas and seed data (`database/` subdirectory).

## Common Tasks & Commands

Database tasks are coordinated through scripts in `database/scripts/` or the root `Makefile`:

```bash
# Execute these from the project root directory
make run_database       # Rebuild and start the Postgres container, running migrations and seed scripts
make migrate_database   # Apply new migrations without rebuilding the container
make connect_database   # Connect to psql shell on the active container
```

## Database Migration Conventions

- Schema updates are managed via append-only SQL migration pairs in `database/migrations/`.
- Naming format: `NNN_description.up.sql` (to apply schema) and `NNN_description.down.sql` (to rollback).
- Numbering must be sequential and padded with three digits (e.g. `001_init_tables.up.sql`, `004_indicator_tables.up.sql`).
- Do not modify existing migrations (`001` - `005`). Any schema changes must be added as `006_name.up.sql` and `006_name.down.sql`.
- Every table modification or new table must have a rollback script in its corresponding `.down.sql` file.

## Seed Data & Initialization

- Raw SQL seed data is stored in ./data/seed_data.sql.
- Container startups automatically run ./scripts/import_seed_data.sh to verify and import base records.

## SQL Formatting & Design Rules

### Code Formatting & Styling
- **Keyword Capitalization**: Write standard SQL statements and types in uppercase (e.g., `CREATE TABLE`, `ALTER TABLE`, `ADD CONSTRAINT`, `SELECT`, `INSERT INTO`, `BIGINT`, `NUMERIC`, `NOT NULL`, `DEFAULT`, `ON DELETE CASCADE`).
- **Identifier Naming**: Write tables, columns, indexes, and constraints in lowercase, snake_case (`daily_prices`, `ticker_id`, `idx_daily_prices_date`).
- **Indentation**: Use 4 spaces for columns and constraint definitions inside `CREATE TABLE` and similar structures.
- **Semicolons**: Every SQL statement must end with a semicolon `;`.

### Database Design Rules
- **Idempotency**: Ensure that your migration scripts are repeatable. Use `IF NOT EXISTS` or `IF EXISTS` where appropriate:
  ```sql
  CREATE TABLE IF NOT EXISTS tickers (...);
  DROP TABLE IF EXISTS tickers CASCADE;
  ```
- **Primary Keys**: Always define as `INT8 GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`. Do not use plain `INT`.
- **Foreign Keys**: Must match PK type (`INT8 NOT NULL`). Include descriptive constraint name starting with `fk_` and ensure `ON DELETE CASCADE` is set.
- **Prices & Currency**: Store monetary values using `NUMERIC(18, 4)`. Avoid floating-point types (`float`, `real`).
- **Volume & IDs**: Volume fields and IDs must be mapped to `BIGINT`.
- **Booleans**: Always define booleans with an explicit default value: `BOOLEAN NOT NULL DEFAULT FALSE`.
- **PostgreSQL Reserved Words**: Never use reserved keywords (`user`, `type`, `order`, `interval`, `table`, etc.) for column names. Use alternatives (`order_type`, `timeframe`, etc.).

### Migration Verification
Before proposing a PR or finalizing the change:
1. Re-run local migration setups via:
   ```bash
   make run_database
   ```
2. Verify that the Docker migration container executes without syntax or relation errors.
3. Verify that the database schema precisely aligns with the JPA configuration fields in the backend (entity properties, scale, precision, column names, constraints).
